DOCUMENTAÇÃO, ARQUITETURA E IA

O que se entende quando fala:
- algo para consulta
- registro
- funcionalidades
- informações organizadas

A transição entre "programador" e "Engenheiro de software" exige uma habilidade crucial: saber comunicar e padronizar o que seu sistema faz antes mesmo de modificá-lo.

O "caos" do acoplamento
 o que acontece em uma empresa quando o backend constrói uma API sem documentação.
- Atrito entre equipes: o frontend tenta adivinhar os campos


A batalha dos paradigmas:
- Code-First (O tradicional)
	- o código nasce primeiro
	- depois, documenta-se o que foi feito
	- problema: o front fica bloqueado esperando o backend terminar. A documentação vira um fardo e rapidamente fica 
- API Firts (O enterprise)
	- O documento nasce primeiro
	- frontend e backend codam simultaneamente baseados no documento
	- vantagem: a documentação é o centro do projeto. Ninguém escreve o código sem planejar antes.

Superpoderes do API-Firts
Porque os gigantes como Netflix e Nubank amam ter um currículo por fora? porque o documentado não serve só para a leitura
- Mock Servers Instantâneos: Ferramentas leem o currículo e cria um servidor "falso" na hora. O frontend testa telas perfeitamente sem o backend ter escrito uma linha de node.js
- SDK generation automatics: ferramentas tem o currículo e geram as funções de requisição sozinhas. Máquinas escrevendo o código para máquinas.

A confusão clássica:
Muitos Devs acham que são a mesma coisa, mas existe ma diferença estrutural enorme
- OpenAPI (a regra): é a especificação. Um padrão global e independente de linguagem. É um arquivo textual que diz como uma API deve ser desenhada e controlada.
- Swagger (A ferramenta): é o software. um conjunto de ferramentas que consome o projeto do OpenAI e o transforma em algo útil.

Níveis de documentação:
- N1 Markdown: o bom e velho arquivo .md. ótimo para leitura no GitHub, mas 100% estético. não dá pra testar __.
- N2 Postman Collection: Excelente para devs testarem localmente. Ruim para compartilhas publicamente e manter equipes sincronizadas.
- N3 Contratos dinamicos :o padrão ouro da energia clássica. um portal interativo dentro do servidor.
- N4 IA : A documentação se torna orgânica e automatizada.
	- Engenharia de prompt para APIs: o arquivo pede: "Gere um contrato openAPI para um e-comerce". Em 5 segundos, a ia gera o JSON/YAML, estruturado perfeito

IA na prática: engenharia aumentada
- Documentação Reversa: se o desenvolvedor herda um sistema legado gigantesco sem documentalão, a IA consegue varrer o registro inteiro e reconstrói o contrato OpenAPI do zero.
- Code Generation Inteligente: Ao aprovar um contrato OpenAPI podemos mandar IA escrever a base do backend conectado as rotas automaticamente. O humano foca só na regra de negocio.
